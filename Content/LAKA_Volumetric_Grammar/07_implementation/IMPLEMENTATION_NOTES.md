# Implementation Notes and Explicit Qualifications

**Status:** New LAKA design material added while packaging the conversation. These notes clarify operation without replacing the user’s axes or presenting additions as PI doctrine.

## 1. Preserve the three axes

The five columns, ten internal variables, and fourteen meta-variables remain exactly as supplied. Their machine codes are stable identifiers. A coordinate identifies a type of question; add separate run, context, hypothesis, and evidence identifiers for actual analyses.

## 2. Baseline is a reference, not zero

Baseline records what is happening now. It can contain large, rapid, widespread, continuous, adaptive, or irreversible processes. The examples in the original internal grid, such as “manual, delayed, or periodic” Feedback, are starting illustrations, not compulsory facts about every baseline.

## 3. Change level is independent of dynamic state

A minor parameter change can propagate worldwide. A paradigm redefinition can begin slowly in one small team. A Structural Change can improve reversibility rather than reduce it. Do not force the five illustrative words in a meta-variable ladder to correspond to the five change columns. Higher is not automatically better.

## 4. The original state ladders are not operational measurement scales

The draft’s ladders mix quantities, categorical descriptions, and mechanisms. They remain useful prompts but cannot be averaged, multiplied, or used as quantitative evidence without a justified operational definition. In particular, a fast rate is not acceleration; persistence is not frequency; the number affected is not the amount each changes; observing a signal is not observing a future event.

Define the property and unit separately in every applied analysis. Use an explicit category when measurement is not available. Record missing values as unknown, not as zero. State the observation period and comparison reference.

## 5. The count means questions, not guaranteed innovations

There are 700 base coordinates under these design choices. Some are inapplicable in a given Scenario; some overlap; some yield multiple candidates. The variables are not assumed statistically independent. The 700 cells do not prove completeness, novelty, feasibility, market demand, or forecast accuracy.

The number of proposed state combinations is different from the number of base coordinates. Do not multiply choice counts and report the result as distinct workable innovations without checking compatibility.

## 6. Use explicit relationship records

A useful dependency record has a source transformation, target transformation, relationship type, mechanism, sign if applicable, delay, evidence, and uncertainty. Suggested types are `requires`, `enables`, `inhibits`, `conflicts_with`, `substitutes_for`, and `feeds_back_to`.

Check pairs before composition, then check the whole system. Pairwise compatibility alone does not prove higher-order compatibility. Feedback cycles may be legitimate; impossible prerequisite cycles need resolution.

## 7. Resolve vocabulary overlaps locally

An item may serve different roles in different Actions. A spreadsheet can be a Tool when it performs a calculation and a Resource when it supplies information. A temperature can be a Condition and can also be intentionally used as a Resource. Preserve role-specific records rather than forcing one universal category.

The system sentence is a modeling grammar, not a literal claim that grammatical subject and acted-upon object are interchangeable in English syntax. The Actor is explicit in the context envelope.

## 8. Outcome redefinition changes comparison boundaries

PI treats required Outcomes as fixed within a defined Scenario [PI-16]. The LAKA Paradigm column allows purpose or success-definition changes. That is a LAKA extension. When it happens, version or create the Scenario and document what changed. Do not claim better performance on an unchanged task after substituting a different task without disclosure.

## 9. Reverse analysis is not uniquely invertible

Several mechanisms may produce the same observation. A decoded fingerprint is a structured hypothesis, not an identity signature or proof of intent. Require alternative explanations, provenance, counterevidence, and discriminating tests. Do not infer private motives, culpability, or wrongdoing from word choice or pattern similarity alone.

## 10. Forecasts need resolution and calibration

A direction of improvement is not evidence that adoption will occur. State what must happen, by when or after which trigger, under which assumptions, and what would disconfirm the claim. Maintain a dated forecast ledger and evaluate it after resolution. Record numeric probability only with a defensible basis; otherwise use explicit uncertainty.

## 11. Recursion is bounded decomposition

A child volume must have a narrower Scope, a clear interface to the parent, and a stopping rule. Suggested default: recurse only on unresolved mechanisms that materially affect a decision. Depth limits and time budgets are configurable workflow choices, not properties proved by LAKA.

## 12. Stable behavior has three useful subtypes

When using STABILIZE, distinguish keeping a desired state, moving to a desired stable state, and returning after disturbance. Those distinctions are inspired by the separate PI Directions, not substituted for the LAKA columns [PI-14].

## 13. Evaluate with hard gates and separate uncertainty

Test physical feasibility, permissions, safety, hard budget limits, and required Outcomes before a weighted desirability score. Do not average a disqualifying failure into an attractive overall rating. Unknown evidence is a reason to investigate, not permission to fabricate a score.

## 14. The package is a specification, not an autonomous application

Markdown, JSON, prompt libraries, and a schema support implementation. The archive does not contain a production causal inference engine, a calibrated forecasting model, automatic research access, a deployed knowledge graph, or guaranteed idea generation. “Run LAKA” is a reusable prompt/reporting convention unless an application explicitly implements it.

## 15. Distinguish sources from extensions

The source book is retained as supplied. The LAKA axes originate with the user. The volume, six-mode architecture, operator library, example concepts, templates, schema, and evaluation safeguards are proposed design work from this conversation. The source’s promotional, universal-completeness, medical, and success-rate claims are not adopted as verified evidence for LAKA.
